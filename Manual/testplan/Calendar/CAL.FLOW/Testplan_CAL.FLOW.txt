# Cross-feature integration journeys for Calendar — CTO-flagged hot
# spot ("issues with Booking Appointments and other things"). Each TC
# walks a user journey end-to-end across the Calendar surface, the
# embedded booking sheet, and the embedded Add Patient sub-modal.
#
# Selectors anchored on the live markup probed via
#   `npm run explore:calendar-flow`
# (output: Automation/calendar-flow-probe.json) and the prior CTO probe
# (Automation/cto-flows-probe.json).
#
# Implementation: tests/calendar/calendar-flow.spec.ts — single spec
# file with `test.describe.serial` and an `afterAll` cleanup that
# deletes every appointment + patient this run created.
#
# Scope notes:
#   • The 4 bottom-right CTAs include #new_meeting, #new_instantmeeting
#     and Create Event in addition to Book Appointment. This plan covers
#     ONLY Book Appointment in depth; meetings + events get presence
#     checks in CAL.FLOW.002 only and own deeper plans later.
#   • Treatment + Practitioner field exercise is parked as a placeholder
#     — those drop-downs depend on per-clinic config and need the data
#     factory layer (Sprint A item) before automation pays off.

Navigating back to the dashboard works between the two clicks. <AUTOMATION>
    <TBD>TC.CAL.FLOW.002 Verify the Calendar page renders ALL expected chrome elements: mini-datepicker (.datepicker.datepicker-inline) on the page; view-mode toggles Day (.fc-agendaDay-button) / Week (.fc-agendaWeek-button) / Month (.fc-month-button); a "Today" button reachable via [class*="fc-today"] or text "Today"; "Day Sheet" anchor; "Task Board" anchor; four booking entry points (#new_appointment "Book Appointment" / #new_meeting "Book Meeting" / #new_instantmeeting "Instant Meeting" / Create Event link with href ending /events). <AUTOMATION>
    <TBD>TC.CAL.FLOW.003 Verify calendar interactivity: (a) clicking a non-today day cell on the mini-datepicker (.datepicker.datepicker-inline .day:not(.disabled,.old,.new)) updates the FullCalendar grid (the toolbar's currently-active view re-renders with the chosen date in scope); (b) clicking the "Today" button after navigating away returns the FullCalendar grid to today's date (today's day-cell carries an "active" / "today" class on the mini-datepicker); (c) clicking each of Day/Week/Month view-mode toggles renders the corresponding view without console errors. <AUTOMATION>
    <TBD>TC.CAL.FLOW.004 Verify Book Appointment HAPPY PATH end-to-end: click #new_appointment → modal #new_appointment_form opens with title "Create Appointment" → click "Add Patient" inside the modal → sub-modal #new_patient_form opens → fill required fields (patient_firstName / patient_lastName / patient_countryCode / patient_phone) → click #confirm-patient-form → sub-modal closes → typeahead #appointment_patient is auto-populated with "FirstName LastName" → fill #appointment_start + #appointment_end → click #save_appointment → modal closes → appointment block appears on the FullCalendar grid (.fc-event) carrying the patient's name within 5 s. <AUTOMATION>
    <TBD>TC.CAL.FLOW.005 Verify bulk-book 5 patients × 5 appointments: in a single test run, repeat the FLOW.004 happy path 5 times — 5 unique markered patients (created via the in-modal #new_patient_form), 5 distinct timeslots (NOT overlapping). All 5 appointments must appear on the grid as .fc-event blocks bearing the respective patient names. Capture per-iteration cycle timing (T1..T5); assert max(T2..T5) < T1 * 2.5 (no significant regression). <AUTOMATION>
    <TBD>TC.CAL.FLOW.006 Verify multiple patients booked into the SAME time slot: take 2 of the 5 markered patients from FLOW.005 → book each into the SAME start/end window via #new_appointment → both bookings succeed (no conflict error fires) → both .fc-event blocks render at the same slot, distinguishable by patient name. (If the app DOES enforce same-slot exclusion as a business rule, document the actual error path — this case becomes a regression watch.) <AUTOMATION>
    <TBD>TC.CAL.FLOW.007 Verify same patient booked at MULTIPLE different times: take 1 of the 5 markered patients → book 3 distinct, non-overlapping appointments for them → all 3 .fc-event blocks render. Then click into the patient detail page (/patients/{id}/appointments) AND verify all 3 appointments are listed. <AUTOMATION>
    <TBD>TC.CAL.FLOW.008 Verify duplicate-appointment behaviour — same patient AT THE SAME TIME: attempt to book the same patient into a slot already occupied by an existing appointment for that patient. Capture the actual app behaviour: silent success (creates a duplicate row), silent failure (no event added, no error), explicit error (toast / inline message), or block (Save disabled). Document the observed behaviour as the assertion target so a regression flips the test red. <AUTOMATION>
    <TBD>TC.CAL.FLOW.009 Verify the booking modal exposes ALL expected option checkboxes — #appointment_allDay (label "All Day"), #appointment_repeat ("Repeat"), #appointment_newPatient ("New Patient"), #appointment_blocker ("Blocker").
