# CTO-flagged frequent-breakage area (raised 2026-05-07): "Sending
# messages/emails are inconsistent — High variance — All buttons and all,
# especially the icons on chat messaging labels (Patients / Prospects /
# Clinics)."
#
# This sub-feature covers the small per-record send icons that appear on
# Patient detail, Prospect detail, and Clinic context bars (the icon row
# next to a record that triggers email / SMS / chat send).
#
# Failure-mode classes the CTO's framing implies:
#   • Icon click handler intermittently does not fire (race with widget
#     init / jQuery plugin not yet bound)
#   • Toast says "Sent" but message never dispatches (need DELIVERY
#     verification, not UI verification alone)
#   • Recipient-resolution wrong (e.g. sends to the test address even after
#     swap)
#   • Template variable rendering breaks (e.g. {{firstName}} renders empty)
#
# Because send-icon selectors will be hairy (icon-only buttons, often
# unlabeled), an early concrete deliverable is to push the dev team for
# data-testid attributes OR aria-labels on each send icon.
